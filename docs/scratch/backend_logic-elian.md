**구상**
--

API → 서비스(주사위 굴리기 → 게임 이벤트) → 리포지토리 

→ DB 반영 완료(성공) 확인 직후 GM이 서사 만들어 리턴

1. API: 전투 또는 상호작용 행동 요청
   - 입력
     - 플레이어 아이디
     - 세션 아이디: 현재 진행중인 스토리 상태(세션) 식별
     - 플레이어 입력 텍스트
       - 예) "천마군림보를 시전한다", "나는 불의를 보면 소멸..."
       - GM이 입력 텍스트만 보고 어떤 행동인지 판단
   - 반환 타입 필수 속성
     - 현재 체력
     - 피해/치유량
     - 상태이상(버프, 디버프, 죽음)
     - GM 응답 메시지(주사위 낮으면 악의적 돌발 연계 이벤트도 종종 진행)
     - 선택지
     - 현재 스테이지 클리어 여부(옵션?)
     - Graph Status Delta
       - 이번 턴에 그래프 DB에서 어떤 노드/엣지가 어떻게 변했는지

2. 서비스
   - API 호출 유형대로 몇 가지 이벤트를 상정
   - GM의 선택에 따라 이벤트 서비스 호출
   - GM용 프롬프트 실행
     - ① 플레이어 요청 
     - ② LLM(Agent)이 요청 해석
       - 필요한 스킬과 난이도 정보를 RDB(스킬 테이블)에서 조회하고 
       - 그래프 DB(상태)를 참조하여 주사위 굴림 요청을 구조화
     - ③ LLM이 Cypher 쿼리 생성 
     - ④ 리포지토리(DB) 호출 및 검증(Graph Traversal) 
       - 주사위 굴림을 여기서 실행(서버 사이드에서 주사위 함수 호출)
       - 주사위 결과 + RG(룰)에 따른 판정
       - 성공/실패 여부 확정
     - ⑤ 결과 획득 
     - ⑥ LLM이 결과를 기반으로 서사 생성 
       - 그래프 DB 조회 / 랭그래프 검증 순회
       - 검증 후 악의적 또는 호의적 돌발 연계 이벤트 최적의 서사 생성
     - ⑦ API 리턴(JSON - 논의)

3. 리포지토리
   - 그래프 DB
      - 서비스에서 호출 가능한 그래프 DB 쿼리 템플릿을 만들어 리포지토리 단에 배치
      - 사건 및 이야기 흐름 등록
        - 전투 경과
        - 획득/보유 아이템(RDB? 그래프 DB?)
        - 등장인물 적대/우호도 관계(서사 DB와 별개로 필요할지도)
      - 스테이지
        - 스테이지 선후 관계 
        - 다음 스테이지로 가기 위한 조건
   - RDB: 
     - LLM이 맘대로 정하는 게 아니라 사전 설정집처럼 써야 하는 정보
     - 워낙 설정이 어려우니, LLM에게 도움을 받아 제안받아야 할지도 모름
     - 주요 테이블
       - 성격(LLM이 새로운 등장인물을 만들때 사용할 재료)
       - 스킬(직업별 LV별로 상이 - LV 시스템과 난이도를 고려)
       - 등장인물(프로필)
         - 단, 등장인물의 세션에서의 상태 및 적대/우호도 정보는 그래프 DB에서 관리
   - VectorDB
     - 스테이지 공략 정보(스토리 요약)
     - 긴 상호작용 로그
       - 플레이어와 GM의 긴 대화 로그를 벡터로 저장
       - LLM이 과거 맥락을 빠르게 회상하고 불필요한 서사 모순 방지
